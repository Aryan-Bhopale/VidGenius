## 🚀 Getting Started

If you’re new to open source, welcome aboard!  

To start contributing:

1. Read this guide thoroughly.  
2. Fork this repository.  
3. Clone your fork locally.  
4. Set up the project using the instructions below.  
5. Pick an open issue or propose a new idea via [Discussions](https://github.com/Thakurbhanupratap/VIDGENIUS/discussions).  

💡 **Tip:** Don’t hesitate to ask questions — we love mentoring new contributors!

---

## 🛠️ Ways to Contribute

You can contribute in multiple ways:

- **💻 Code** — Fix bugs, add features, optimize performance.  
- **📝 Documentation** — Improve guides, tutorials, or translations.  
- **🎨 Design/UI** — Suggest UI/UX improvements or create visuals.  
- **🐞 Bug Reports** — Identify issues and provide clear reproduction steps.  
- **💬 Discussions** — Help answer community questions and share ideas.

---

## ⚙️ Development Setup

1. **Fork the repository** on GitHub.  
2. **Clone your fork** locally:
   ```bash
   git clone https://github.com/<your-username>/VIDGENIUS.git
   cd VIDGENIUS
   ```
   
3. **Add upstream to sync changes:**  :
   ```
   git remote add upstream https://github.com/Thakurbhanupratap/VIDGENIUS.git
   ```

4. ** Install dependencies **:
  ```
  pip install -r requirements.txt
  ```

5. Run the project locally to verify your setup:
  ```
   streamlit run src/app.py
  ```

## 🧩 Submitting Changes

1. **Create a new branch** for your feature or fix:
   ```bash
   git checkout -b feature/your-feature-name
   ```

2. Make your changes and commit them with **a clear, concise message**:
   ```
   git commit -m "feat: add user profile page"
   ```

3. Push your branch to your fork
   ```
   git push origin feature/your-feature-name
   ```

4. Open a Pull Request (PR) to the main branch.


## 🧹 Code Style Guidelines

To maintain code quality and readability:

- Follow the naming conventions used in the project.  
- Use **Prettier** or **ESLint** (if applicable).  
- Write clear, self-documenting code.  
- Add comments for complex logic.  
- Keep commits atomic — one logical change per commit.  

💡 **Tip:** Run formatting and linting before submitting a PR.

## 🐛 Issue Reporting

If you find a bug:

1. Search existing issues to avoid duplicates.  
2. If it’s new, open a **bug report issue**.  
3. Include the following details:
   - Steps to reproduce the bug  
   - Expected vs actual behavior  
   - Screenshots or logs (if applicable)  
   - Environment details (OS, version, etc.)  

---

## 🔄 Pull Request Guidelines

To ensure smooth review:

- Fill out the PR template completely.  
- Reference related issues using `Fixes #<issue-number>`.  
- Keep PRs small and focused.  
- Be ready to update your PR based on feedback.  

After approval, maintainers will merge your PR.
